# Схемник

Редактор принципиальных схем в браузере: электрика, гидравлика и пневматика в одном многолистовом проекте, с перекрёстными ссылками между листами, перечнем элементов по ГОСТ 2.701, таблицей входов/выходов PLC и экспортом в PDF со штампом по ГОСТ 2.104.

Один файл `shemnik.html`, без сборки, без сервера, без установки. Рисует на SVG, логика — vanilla JS.

---

## Запуск

Открыть `shemnik.html` в браузере (Chrome / Edge / Firefox / Safari). Интернет нужен только для двух вещей с CDN:

- шрифты IBM Plex (Google Fonts) — без них используется системный шрифт;
- jsPDF 2.5.1 (cdnjs) — без него не работает только экспорт в PDF, печать и всё остальное работают.

Рабочее состояние автоматически сохраняется в `localStorage` браузера. Это черновик, а не хранилище: он привязан к адресу файла и браузеру. Проекты храни в файлах — **Файл → Сохранить** (Ctrl+S).

> В Chrome / Edge сохранение работает как в обычной программе: первый раз спрашивает куда, дальше Ctrl+S перезаписывает тот же файл (File System Access API). В Firefox / Safari файл каждый раз скачивается в «Загрузки».

## Возможности

- **Листы проекта** (вкладки). Вид листа: **Э** — электрическая, **Г** — гидравлическая, **П** — пневматическая, **С** — совмещённая. Палитра показывает только элементы своего вида. Листы переставляются перетаскиванием вкладок или кнопками ◀ ▶ в свойствах листа.
- **Одно устройство — несколько представлений.** Электроклапан YV1 на Г3 — корпус на трубе, на Э3 — катушка; связь по позиционному обозначению. Под элементом — ссылки «катушка → л.2», по клику переход на нужный лист.
- **Контакты реле с нумерацией по МЭК 60947**: первая цифра — порядковый номер контакта у реле, вторая — функция (1-2 NC, 3-4 NO): 13-14, 21-22, 33-34… Под катушкой — «зеркало контактов».
- **Три среды соединений**: провода (чёрные), вода (синие трубы), воздух (зелёные). Разные среды соединить нельзя.
- **Флажки линий** (ввод/выход L1, N, +24 В…): флажки с одинаковым именем — одна цепь, в том числе между листами.
- **Автотрассировка** проводов (A\*, обход корпусов, разные цепи не идут по одной линии) + ручная правка сегментов с закреплением.
- **Контроллер** с настраиваемым числом DI / DQ / AI / AQ; выводы подписаны адресами S7-1200 (I0.0…, Q0.0…, IW64…, QW64…). Размер корпуса тянется ручкой в углу: вбок — ширина, вниз — шаг выводов (по сетке).
- **Автоадресация PLC**: устройство, подключённое к выводу контроллера, само получает адрес — сквозь барьер искрозащиты и через флажки на других листах. Ручной адрес главнее; расхождение «вписан Q0.3, а провод на Q0.2» подсвечивается.
- **Перечень элементов** — таблица прямо на листе, одинаковые элементы с подряд идущими номерами сводятся (R1…R3), устройство на нескольких листах считается один раз.
- **Штамп** (вкладка «0 · Штамп»): лист 1 — форма 1 (сокращённая 185×30 или полная 185×55), остальные — форма 2а (185×15). Шифр листа = шифр изделия + код листа (Э3, Г3, П3).
- **Экспорт**: PDF (все листы, рамка + штамп), JPG / SVG текущего листа, печатный вид, перечень CSV, теги PLC для TIA (CSV), JSON.

## Управление

| Действие | Как |
|---|---|
| Добавить элемент | меню групп в шапке или поиск «Найти элемент…» (Enter — добавить первый найденный) |
| Провод / труба | тянуть от вывода к выводу, или тап по выводу, потом по второму |
| Выделение рамкой | ЛКМ по пустому месту. Слева направо — только целиком попавшие, справа налево — все задетые |
| Добавить/убрать из выделения | Shift+клик, Shift+рамка |
| Двигать чертёж | ПКМ или зажатое колесо (на телефоне — палец по фону) |
| Масштаб | колесо (к курсору), щипок на телефоне |
| Сдвинуть сегмент провода | выделить провод, тянуть квадратные ручки — путь закрепится |
| Повернуть / удалить | R / Del |
| Сдвиг выделенного на клетку | стрелки |
| Выделить всё на листе | Ctrl+A |
| Отменить | Ctrl+Z |
| Сохранить / Сохранить как / Открыть | Ctrl+S / Shift+Ctrl+S / Ctrl+O, или перетащить файл проекта в окно |
| Излом провода (режим «уголком») | двойной клик по проводу или F |
| Снять выделение, закрыть меню | Esc |

## Элементы

Код в скобках — буквенный код позиционного обозначения. `[Г]`, `[П]` — только на листах этого вида, `[С]` — только на совмещённом.

**Питание:** Питание (PWR), Земля, Блок питания (G: L, N, +, −), Трансформатор (TV: 1-2 / 3-4), Автомат (QF), Батарея (GB), Ввод / Выход линии эл. (флажки).

**Коммутация:** Выключатель (SA), Кнопка NO / NC (SB), Контакт NO / NC реле (K), Контакт PLC LAD (K).

**Реле и нагрузки:** Катушка реле (KA), Выход PLC LAD (KM), Катушка клапана (YV), Регулятор давления — управление (РД: +24, 0В, I+, I−), Лампа сигнальная (HL), Светодиод (HL), Двигатель 1~ (M), Двигатель 3~ (M: U1, V1, W1, PE).

**Датчики:** Датчик давления 4…20 мА (BP), Датчик потока 4…20 мА (BF), Контакт прессостата (SP), Прессостат совмещённый `[С]`.

**Автоматика:** Контроллер PLC (A), Барьер искрозащиты (A: 1, 3 — Ex-зона; 7, 8 — выход; 14, 15 — питание).

**Пассивные:** Резистор (R), Конденсатор (C), Диод (VD).

**Гидравлика `[Г]`:** Ввод / Выход линии, Шаровой кран (V), Фильтр воды (F), Электроклапан (YV), Датчик-реле давления (SP), Датчик давления PT (BP).

**Пневматика `[П]`:** Ввод / Выход воздуха, Вентиль ручной (V), Редуктор (КР), Регулятор давления электропневматический (РД), Пневмоклапан (YV), Датчик давления PT (BP), Датчик потока FT (BF).

**Оформление (любой лист):** Сноска — многострочный текст на полке, выноска с точкой / стрелкой, кончик перетаскивается.

Пары представлений (одно обозначение на разных листах): катушка клапана ↔ электроклапан / пневмоклапан, контакт прессостата ↔ датчик-реле давления, датчик давления ↔ PT, датчик потока ↔ FT, регулятор давления (упр.) ↔ регулятор (корпус), катушка реле → контакты NO / NC.

## Формат файла проекта (`*.shema.json`)

Обычный JSON, удобно хранить в git.

```json
{
  "n": 100,                       // счётчик для новых id
  "cur": "s1",                    // открытый лист
  "route": "auto",                // "simple" — провода уголком без трассировки
  "sheets": [
    { "id": "s1", "name": "Г3 Гидравлика", "kind": "Г" },
    { "id": "s2", "name": "Э3 Электрика",  "kind": "Э", "code": "Э3" }
  ],
  "comps": [
    { "id": "g4", "type": "YVH", "sheet": "s1", "x": 420, "y": 100, "rot": 0,
      "ref": "YV1", "val": "НЗ, 24 В", "note": "" },
    { "id": "e6", "type": "YVE", "sheet": "s2", "x": 340, "y": 200, "rot": 0,
      "ref": "YV1", "val": "НЗ, 24 В", "io": "Q0.0" }
  ],
  "wires": [
    { "id": "w3", "a": ["g3", "вых"], "b": ["g4", "вх"] },
    { "id": "w7", "a": ["e1", "1"], "b": ["e5", "13"], "pts": [[100,60],[100,200],[160,200]] }
  ],
  "bom":   { "show": true, "sheet": "s2", "x": 580, "y": 20 },
  "stamp": { "code": "АБВГ.421000.001", "title": "Узел подготовки воды", "org": "",
             "litera": "О1", "full": false,
             "people": { "dev": { "n": "Иванов", "d": "10.26" } } }
}
```

Поля элемента:

| Поле | Смысл |
|---|---|
| `type` | ключ типа в таблице `T` (см. ниже) |
| `x`, `y`, `rot` | положение (сетка 20) и поворот 0 / 90 / 180 / 270 |
| `ref`, `val`, `note` | обозначение, номинал, примечание в перечень |
| `io` | ручной адрес PLC (пусто — адрес по подключению) |
| `pos` | ручной номер контакта реле (пусто — авто) |
| `ndi`, `ndq`, `nai`, `naq` | число каналов контроллера |
| `pw`, `pp` | контроллер: полуширина корпуса (40…300) и шаг выводов (20…100), кратны 20; нет — по умолчанию 60 и 20 |
| `tx`, `ty`, `lead` | сноска: кончик выноски и вид (`dot` / `arrow` / `none`) |

Провод хранит **выводы**, а не координаты: `a`/`b` = `[id элемента, имя вывода]`. Поэтому провода сами идут за элементами. `pts` есть только у вручную закреплённых путей. Связь между листами — только через одинаковые `ref` (представления устройства) и одинаковые имена флажков линий.

## Как устроен код

Всё в одном `<script>` в конце файла. Основные части:

| Что | Где / функция |
|---|---|
| Описания элементов | `const T = { R: {...}, KA: {...}, ... }` |
| Состояние проекта | `S` — то, что сохраняется в JSON; `sel`, `view`, `vb` — состояние интерфейса |
| Отрисовка | `render()` → `compSVG()`, `wireSVG()`, `dotsSVG()`, `bomSVG()`, `handlesSVG()` — строки SVG в `innerHTML` |
| Выводы экземпляра | `TP(c)` — описание типа с учётом экземпляра (у контроллера и сноски выводы и размер вычисляются: `dyn`) |
| Трассировка | `routeAll()` — A\* по сетке 20 px, состояние «клетка + направление», штрафы за изломы и чужие цепи |
| Цепи | `nets()` — union-find по проводам текущего листа |
| Автоадреса PLC | `autoIO()` — union-find по всем листам + флажки + проход сквозь барьер |
| Перечень, I/O, TIA | `bomRows()`, `ioRows()`, `tiaCSV()` |
| Штамп | `stampSVG(sheet, n, m, form, px/мм)` — SVG в миллиметрах |
| Экспорт | `exportSVG()` → `rasterize()` → `sheetCanvas()` → jsPDF; сохранение `offer()` |
| Файл проекта | `saveProject()`, `openProject()`, `loadProjectText()`, `migrate()` |
| Отмена | `push()` перед каждым изменением кладёт снимок `S` в `hist`, `undo()` — снимает |

### PDF

Растровый: каждый лист → чистый SVG (`exportSVG`) → canvas (масштаб до 4×, не больше 8000 px по стороне и 12 Мп — лимит Safari) → лист A4 297×210 мм при 8 px/мм с рамкой и штампом → `jsPDF.addImage(JPEG 0.9)`. JPEG, а не PNG: PNG в jsPDF раздувает файл в десятки раз. Векторный вариант — `svg2pdf.js` + встроенный кириллический шрифт (не сделан).

Сохранение: открыт с компьютера — `<a download>` с blob; внутри claude.ai (артефакт) — через `window.claude.use('downloads')`, потому что песочница блокирует прямое скачивание.

## Как добавить свой элемент

Добавить запись в `T` и (по желанию) в группу меню `GROUPS`:

```js
// внутри const T = { ... }
XS: {
  name: 'Концевой выключатель',   // в меню и в перечне
  pre:  'SQ',                     // буквенный код → SQ1, SQ2…
  val:  '',                       // номинал по умолчанию
  pins: [['1',-40,0], ['2',40,0]],// [имя, x, y, среда?]; среда: 'h' — вода, 'n' — воздух, нет — провод
  box:  [-40,-18,80,30],          // габарит [x, y, ширина, высота] — для выделения и обхода трассировкой
  d:    '<path d="M-40 0H-12M12 0H40M-12 0L14 -12"/><path d="M14 -12l6 -6"/>',  // символ, локальные координаты
  showPins: true,                 // подписать выводы на чертеже
},
```

Выводы ставить в точки, кратные 20 (сетка), иначе трассировка их не найдёт. Остальные необязательные поля:

| Поле | Зачем |
|---|---|
| `k` | вид листа: `'Э'`, `'Г'`, `'П'`, `'С'`, `'*'` — везде (или добавить код в список `['R','C',…].forEach(k=>T[k].k='Э')`) |
| `split` | раздельное представление — не показывать на совмещённом листе |
| `pair`, `short`, `dev`, `prio` | связь представлений одного устройства: парный тип, подпись в ссылке, имя в перечне, чьё имя главнее |
| `ly`, `vb`, `lx`, `vy` | где рисовать обозначение и номинал |
| `noIo` | не показывать поле «Адрес PLC» |
| `dyn` | функция `c => ({pins, box, d, …})`, если вид зависит от экземпляра |

В классах SVG: `pp` — линия трубы (вода), `pa` — линия воздуха, `fill` — заливка цветом линий, `pf` / `paf` / `paw` — стрелки сред.

Для автоадресации PLC — добавить тип в `IN_PRI` (входы) или `OUT_PRI` (выходы). Чтобы элемент не попадал в перечень — в `BOM_SKIP`.

## Ограничения

- PDF растровый (~200 dpi на A4): текст не выделяется, при сильном увеличении видны пиксели.
- Листы нумеруются сквозь весь проект; по ГОСТ Г3 и Э3 — отдельные документы со своей нумерацией.
- Импорт тегов в TIA Portal идёт через xlsx; CSV из Схемника — с колонками как в таблице тегов TIA, строки вставляются в xlsx-шаблон из экспорта TIA.
- Нет копирования / вставки групп, клеммников и кабелей (схемы соединений Э4/Э5).
